02 — Selected Work

Systems, not screens.

Production work from enterprise codebases. The source is proprietary, so here's the problem, the decision, and what it cost or saved.

01

Config-Driven Form & Table Builder

Trio Services · Enterprise ERP

Thirty-plus modules were coming and every team was about to hand-build the same screens — linear cost, and a UI that drifted between teams. So I built the layer underneath instead: a Form Builder with 25 control types and custom validators, and a Table Builder data-grid, both driven entirely by configuration. A new screen became a config file, not a new codebase. The trade-off was a slower start and a config model the team had to learn; it paid back from roughly the fourth module on.

  • 30+modules powered
  • 350+components
  • 25control types
  • Angular
  • TypeScript
  • Reactive Forms
  • Component Architecture
02

Runtime Custom Fields Engine

Trio Services · Multi-tenant

Every client wanted their own data fields. The easy answer is a branch per client — which means N codebases to maintain and every bug fixed N times. Instead I designed a metadata model resolved at runtime and rendered generically across every module, with no per-tenant code anywhere in the tree. Onboarding a client with a new data shape became configuration rather than a release.

  • 0lines of per-tenant code
  • Runtimeschema resolution
  • Angular
  • Dynamic Rendering
  • Multi-tenancy
03

Real-Time Notification Layer

Trio Services · SignalR + RxJS

Notifications ran on HTTP polling — wasteful, and still late. Moving to SignalR WebSockets was the obvious half of the fix; the non-obvious half was that naive push is worse than polling, because every message triggers a full change-detection cycle. The real work was in the reactive layer: RxJS streams for delivery, and NgZone tuned so high-frequency events reach the user instantly without the UI paying for each one.

  • Instantpush delivery
  • 0polling requests
  • SignalR
  • RxJS
  • NgZone
  • Change Detection
04

Angular v19 Migration, Without a Freeze

Maxim Investment Group · Legacy SaaS

Legacy SaaS platforms on an old Angular version, with the business still shipping features. A rewrite would have frozen product work for months and bet everything on a single cutover, so I ran it incrementally — upgrading the build tooling and refactoring into a modular, reusable component architecture on the way through. The cost was a period where old and new patterns coexisted, which needed clear conventions to stay manageable.

  • v19landed, no freeze
  • Modularcomponent architecture
  • Angular v19
  • Build Tooling
  • Refactoring
